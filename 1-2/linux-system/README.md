## 🧩 자료별 파일 형식

Linux 자체에 전용 확장자가 있는 것은 아니므로 자료의 성격에 맞게 구분합니다.

| 학습 자료 | 형식 | 용도 |
| :-- | :-- | :-- |
| 명령어와 개념 정리 | `.md` | 명령어 목적, 옵션, 예시와 실행 결과 설명 |
| 실행 가능한 셸 스크립트 | `.sh` | 여러 명령어를 묶은 자동화 실습 |
| 시스템 프로그래밍 | `.c` | Linux 환경에서 작성하는 C 실습 |
| 설정 파일 | 확장자 없음 또는 고유 형식 | 실제 프로그램이 요구하는 이름과 형식 유지 |
| 단순 출력 기록 | `.txt` | 가공이 필요 없는 실행 결과 보관 |

명령어를 단순히 나열하는 자료는 `.txt`보다 `.md`로 작성합니다. Markdown에서는 설명, 옵션 표와 코드 블록을 함께 사용할 수 있어 복습하기 쉽습니다.

<br>

## ✍️ 명령어 기록 형식

각 명령어 문서는 다음 순서로 작성합니다.

```markdown
## 파일 목록 확인

현재 디렉터리의 파일과 폴더를 확인합니다.

```bash
ls -la
```

| Option | Description |
| :-- | :-- |
| `-l` | 권한, 소유자와 크기 등 상세 정보 표시 |
| `-a` | 숨김 파일을 포함해 표시 |

### 실행 결과

직접 실행한 결과와 확인한 내용을 기록합니다.
```

이 형식을 사용하면 명령어의 이름뿐 아니라 사용 목적과 옵션의 차이까지 함께 남길 수 있습니다.

<br>

## 🗂️ 예정 구조

실제 자료가 생기면 필요한 폴더만 단계적으로 추가합니다.

```text
linux-system/
├── commands/
│   ├── file-and-directory.md
│   ├── permissions.md
│   └── process-management.md
├── scripts/
│   └── example.sh
├── system-programming/
│   └── example.c
└── README.md
```

위 항목은 저장 방식의 예시이며, 실제 폴더명과 범위는 강의 구성에 맞춰 결정합니다.

## 📌 정리 원칙

- 명령어 문서에는 목적, 기본 문법, 주요 옵션과 직접 실행한 예시를 기록합니다.
- 위험하거나 시스템 상태를 변경하는 명령어는 영향과 주의사항을 함께 표시합니다.
- 셸 스크립트에는 필요한 실행 권한과 실행 명령을 README에 안내합니다.
- 운영체제와 배포판에 따라 결과가 달라지는 경우 사용 환경을 명시합니다.
- 수업에서 다루지 않은 내용을 학습 완료 항목처럼 작성하지 않습니다.
